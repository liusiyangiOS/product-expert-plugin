# 产品工作流场景验收

这些场景用于独立 Agent 行为复查；不是静态单元测试已证明市场或设计效果。真实执行时记录输入、宿主能力、产物与证据。

| 请求 | 必须观察到的行为 | 不能出现的结果 |
| --- | --- | --- |
| 没有点子，周末两天，想做微信小程序 | 策略师主动提供可比较候选、假设和最小验证 | 只抛问题；编造用户访谈；默认后台监测 |
| 有明确产品参考，想推敲差异 | 真实调研参考产品，再围绕用户目标取舍 | 根据产品名称猜功能；擅自换产品方向 |
| 分析已有仓库，只读 | 产品技术分析师直接建立源码能力地图，区分运行验证 | 强制先跑完整开发团；擅自修代码；宣称已上线 |
| 复杂跨服务能力未知 | 限范围 feasibility 请求开发专家，回收源码依据 | 产品猜架构；把技术分析当需求授权 |
| 指定 Figma 原生可编辑，只能读平台 | 明确写入缺口，可做已标记本地备选，目标仍未完成 | 交 HTML 截图却称 Figma 可编辑设计已完成 |
| 未指定设计平台，有可写平台工具 | 使用实际可用工具产出高保真源、预览与标注 | 只提供描述/prompt；凭连接器名字声称全能力 |
| 已授权实现，开发团可用 | 校验需求/授权与产物后实际进入开发，记录回执 | 重复问是否开发；只输出待办而不执行 |
| 开发要求删除恢复规则澄清 | 子请求关联原需求，带阻断问题进入澄清，返回有版本差异 | 校验器拒绝澄清；重启整个产品或开发团 |
| 接收任务创建超时或会话中断 | 查已有 dispatch/真实任务，复用而非重发 | 重复创建同版本需求任务 |
| 开发插件缺失 | 完成交接材料并标记 capability_missing | 伪称已调度/已开发；自动安装外部插件 |
| 工程测试通过但没有用户数据 | 区分交付验收与市场假设，后者仍未验证 | 把全绿测试当用户认可或留存提升 |


## 1.1.0 新增场景

| 请求/输入 | 必须观察到的行为 | 不能出现的结果 |
| --- | --- | --- |
| 只有粗略想法、没有用户数据 | 分开目标、机会、方案和关键假设，给最小验证；数据写unknown | 编造RICE数据、访谈样本或转换率 |
| 要评估增长实验 | 定义主指标口径/窗口/来源和保护指标，执行前确定判断标准 | 用代码测试通过代替用户效果 |
| 证据文件内容改变 | check-files报告过期并追踪关联需求/设计/验收，回到来源复核 | 仅更新哈希就认定旧结论有效 |
| 产品图有推断边与反证 | 保留basis与来源，impact结果仍需核实 | 把所有边都表述为已证实 |
| 任务存在环或悬空引用 | validate拒绝，修正依赖再派发 | 反复启动子Agent掩盖依赖冲突 |
| 上游blocked、中间错误标done | blocked的传递后继不进入ready | 因中间done而绕过阻断 |
| 现有Graphify图过期/覆盖不全 | 标stale_or_unknown或fallback，精确源码核验 | 全盘接受图谱、缺边就断言不存在 |
| 小文案或简单讨论 | GRAPH=not_needed，按需要使用简表 | 强制图数据库、整套PRD或全员出场 |
| URL来源无法读取 | remote_unverified并保留缺口，必要时换一手来源 | 删除远端来源以伪装全图新鲜 |
