# 产品专家团设计决策

## 命名与职责

采用 product-，覆盖产品策略、需求、研究、体验、UI、技术理解和验证，避免误导为纯 PRD 团队。参考开发团的多角色与工作流组织，但不照搬开发/QA/安全审查的角色名称和职责。

主动构思单列 product-strategist；产品主理人负责调度与持续讨论，避免同时承担所有提案和自审。UX/UI 分开：UX 定义完成任务的方式，UI 产出真实高保真界面；必要时同一简单任务可按顺序承担两种工作，无需强制两个子 Agent。

技术分析师是产品侧的代码与实现证据入口。源码能支持能力判断，不能支持真实用户需求、部署现状或业务成功推断。复杂技术问题以只读子任务请开发团提供证据，产品侧负责价值取舍。

## 产品与开发衔接

单独一个单向入口不足以支持长期迭代，因此采用可被两侧调用的 product-dev-bridge。无需写入 dev-* 即可提供反向入口，但自动选择依赖主理人阅读技能/项目约定；不宣称已向现有开发团注入后台 hook。

同一个主任务可在产品/开发阶段间切换；如果转交调度权，记录接收方、返回地址和暂停状态。开发发起咨询时保留开发调度权，避免两个主理人竞争和递归建团。

交接采用稳定 request_id、revision、parent_request_id、快照与回执。轻量 Python 校验器用于防止明显不完整的派发记录；它不是工作流引擎，不能验证真实授权或实现 exactly-once。恢复须查询实际任务。

## 平台与模型

平台支持通过实际连接器/技能的能力发现扩展，避免硬编码虚构的统一设计 API。原生可编辑源、HTML/SVG、静态图和原型严格分级。用户指定平台无法写入时，备选产物可继续，但不能把原指定目标标为完成。

Codex/Claude 各有独立运行文件和安装状态。维护期生成 Claude 角色和技能内容；运行期没有跨端依赖。默认继承宿主模型，用户覆盖优先，没有复制开发团的模型家族偏好、72 小时缓存或后台行为。这是有意减少前置依赖，不代表已验证某模型更适合产品工作。

## 参考与边界

参考本地 dev-expert-plugin 的角色/技能双端包装、普通文件安装、冲突预检/备份、路径检查、回滚和隔离宿主测试。安装器去除旧开发角色迁移白名单，新增产品专属命名与清单身份校验；未读取或复制个人凭据、会话或模型缓存。

本次只在指定空目录创建源码和说明，未修改开发团，未安装到真实个人目录，未初始化 Git 或推送发布。项目 Git 行为继续服从用户/项目实时规则，未继承参考仓库“直接改 master”的个人约定。


## 1.1.0 追加决策

通过外部比较补充按需产品方法与Graph，详见比较报告。保留现有8角色/6入口及开发桥接边界，不新增另一套大编排框架。产品图和任务DAG合在一个轻量JSON文件中但语义分离，纯标准库工具负责只读校验、依赖就绪和影响/新鲜度检查；不自动执行图，也不替代真实研究。Graphify仅是可选代码关系证据源，其schema不会直接混入产品图。双端正文同源生成，两端独立安装，升级备份并校验共存。
