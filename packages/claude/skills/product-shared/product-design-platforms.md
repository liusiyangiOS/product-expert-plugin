# 设计平台适配与交付分级

本协议支持接入不同平台；不表示已实现或实测所有平台 API。实际支持能力取决于宿主当次连接的工具、账户权限和目标文件。无需绑定 Figma，也不安装一批平台作为前提。

## 能力发现与选择

1. 读取用户指定平台、现有文件/组件库、目标终端和交付类型。只在影响产物的关键缺口上提问；否则先提出可调整的视觉方向。
2. 发现连接器/插件/CLI 的真实能力，记录平台、读/创建/编辑/导出/预览、可编辑组件支持、权限与缺口。读取对应平台技能；Figma 的使用/创建/设计等先决技能在调用相关工具前执行。
3. 指定平台优先。在用户未指定时，可用平台中优先已有设计资产所在平台；再考虑能产出可编辑高保真界面的工具。Figma、Penpot、Sketch 等只是可选适配目标，名称出现不证明已连接或可写。
4. 没有合适平台时可以制作本地 HTML/CSS 高保真界面或 SVG 源稿并真实渲染。不能把“可导入”当成已在目标平台创建，不能把 HTML 截图当成原生组件。

## 统一设计交付包

- 需求版本、页面/组件 ID、平台或文件格式、可编辑程度、源文件路径或原生链接。
- 高保真关键页面及所需状态，设计 tokens、组件 variants、实际文案、交互/尺寸说明和资源。
- 预览图片或可打开预览；执行的渲染/打开步骤、检查结果和未覆盖项。
- 需求→页面→组件映射与开发标注；平台切换后的丢失信息和重建要求。

记录 `ARTIFACT_KIND=native-editable|local-editable|static-render|wireframe|interactive-prototype`，同一包可有多个类型。以源文件实际结构判断，不能只按扩展名。生成一张界面图是 static-render；文字描述和提示词不算 UI 交付。

## 扩展新平台

无需新增产品专家。通过现有工具确认能力，建立平台适配记录，执行创建/修改→读取/导出→预览核验。平台只读时只能检查已有设计；写入任务保留未完成状态。外部发布/共享另按用户授权，工具自动发布能力不构成授权。

文件编辑串行分配同一画板/组件，避免覆盖。保留指定设计文件已有内容；每次迭代绑定版本。跨平台转换后核对文字、布局、字体、组件和交互；不承诺无损转换。
