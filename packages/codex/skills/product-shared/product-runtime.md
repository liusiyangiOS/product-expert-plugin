# 本端运行与能力发现

先识别宿主、实际 OS/shell、项目根目录、用户既有授权和可用工具。完整包可单独使用；外部开发团、设计平台和浏览器均是按任务需要发现的可选能力，不读取另一宿主的个人安装目录。

本端资源根为 `~/.agents/skills/product-shared/`，角色在 `~/.codex/agents/`。先展开当前用户主目录再传给工具；不写死作者路径。Python 辅助工具需 Python 3.11+，不自动联网安装解释器。含中文/空格路径使用完整参数；不要把 Bash 语法用于 PowerShell。

## 委派与模型

主任务可以直接充当唯一主理人；按实际可用并发槽位和任务依赖委派。先查看宿主提供的角色类型，使用实际暴露的 product-* 类型；未加载时可以用通用子 Agent 加载本端完整角色说明，但必须说明未使用原生自定义角色。宿主不支持委派时执行授权内的单 Agent 工作，并标记独立评审未执行。

默认继承当前会话模型，不硬编码型号、不共享开发团模型缓存。用户指定模型/推理强度时优先，并核验创建工具实际支持；按工具要求传入真实参数，不能只写在 prompt 里。明确要求更高模型而无法满足时报告缺口，不静默降档。角色声明不是模型调用证据。

## 外部能力

优先使用宿主实际提供的连接器、插件、MCP 或 CLI；工具名和参数从本次发现读取，不虚构固定 API。平台有技能先决条件时先读相应技能。若原生插件有命名空间，实际 skill/角色名称以宿主目录为准；如 Claude 插件显示 `product-expert-plugin:product-design`，使用完整名称，个人安装使用裸名。Codex 使用 `$product-design` 等实际发现名称。

开发协作必须发现同一宿主的 dev-* 入口；缺失时产出交接包并说明未派发，不能凭仓库存在宣称已运行开发团队。发现过程仅核对能力与必要路径，不读取密钥/认证文件。不自动安装或升级外部插件，不自动发布设计稿。

目录扫描与工具回执仅证明相应层级；安装/语法检查不等于宿主已加载、设计写入成功或跨团队开发完成。
